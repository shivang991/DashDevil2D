# Native Go server mechanics and transport diagnostic

`simulation` is a serialized headless round owner for common multiplayer movement, shifts, NOS, next-tick authenticated-intent admission, control freshness and lag abandonment. `configuration` captures canonical JSON settings with semantic/resource validation and private value-owned state. `track` shares xorshift32 and lane/type selection with TypeScript, supports Long Drive anchors and chronological multiplayer placement, and retains stable identities through extension/retirement.

Use Go 1.26.0 from `.go-version`. `go vet ./...`, `go test ./...` and `go build ./...` remain mandatory workspace checks. Native tests consume shared configuration, timeline, geometry, seeded-placement and wire fixtures. Continuous position tolerance is `0.000001 + 1e-12 * abs(expected)`; decisions, integer event times, seed words and identities match exactly.

Call `configuration.Capture` with the canonical `packages/contracts/configuration/defaults.json` definition and optional JSON overrides before creating a round. Pass authenticated seat identities to `simulation.New` and separately to `Submit`; payload identities never authenticate themselves. Call `AdvanceTo` with monotonic seconds since announced round zero. The coordinator must exclude countdown and call `Disconnect` immediately on pair loss. Snapshots/events expose copies. Submit traffic-limit errors require explicit paired failure/recovery by the transport adapter.

Protocol version 1 provides generated binary contracts and handwritten wire-state/resource validation in `protocol/`. Run `pnpm generate` and `pnpm check:generated` from the root after schema changes. Contact/blocking/returns, object interactions and outcomes remain later gameplay slices; this module does not yet implement a complete multiplayer game. See [the #28 checkpoint](../../docs/preservation/mechanics-checkpoint.md).

The workspace build uses `go build -buildvcs=false ./...` so compilation does not depend on access to Git metadata in linked worktrees or restricted build environments. This disables automatic Git revision/dirty-state stamping in Go binaries; acceptance evidence records the tested revision separately. When building directly from this module in the same environment, use that command too.

Stage 4/#29 supplies real HTTPS/WebSocket and HTTP/3 UDP listeners in `transport/`, with executable `cmd/diagnostic` and `cmd/devcert` commands. See [transport setup, contracts and limitations](transport/README.md). Run `pnpm test:transport` from the root in addition to the existing checks. The diagnostic fixture does not start multiplayer gameplay; Stage 4 exit still requires #28 parity and the applicable supported-browser/certificate evidence.

#30 adds product rooms as the executable's default mode. Run `pnpm dev:transport` for the React room UI, `pnpm test:rooms` for its mandatory two-browser scenarios, and `--diagnostic` for the retained Stage 4 fixture. The slice ends at shared round zero; movement is #31. See [room checkpoint](../../docs/preservation/rooms-checkpoint.md) for the owner's completed Stage 4 entry confirmation, evidence and remaining acceptance boundaries.

Persistent username/password accounts, setup, session/security boundaries and authenticated multiplayer are documented in [accounts](accounts/README.md). Product admission fails closed without an account store. The executable opens SQLite through `--database`; Docker mounts the persistent accounts volume. Run `pnpm test:accounts` for the actual login-to-gameplay/logout browser path.
