# Contracts ownership

Canonical language-neutral configuration is in `configuration/defaults.json` (version 1), with owner-approved units, fixed rules, responsibility groups and per-mode defaults. `configuration/fixtures.json` (version 1) records literal valid/invalid expectations and the governing decision link. TypeScript semantic validation and immutable capture live in `@dashdevil/simulation/config`; Go consumes these same definitions/fixtures in #28. Every current root `test` runs the fixture scenarios through Vitest.

The configuration capture API rejects unknown groups, unknown/fixed fields, malformed types, nonfinite values and inconsistent relationships without replacing supplied values. Overrides are developer/test inputs before capture. Long Drive holds its own frozen capture and reset captures again; runtime settings cannot be replaced through the game object. Presentation, room, connection and operational settings stay separate from gameplay. The later lifecycle components must capture their groups at their own agreed boundaries.

#27 introduces the protocol schema, mechanical Go/TypeScript generation, compatibility byte fixtures and stale-generated-output checks. Exact signed fingerprint field widths, continuation record layout and serialized baseline sizing do not exist yet. Current checks cover finite coverage, exact JavaScript projection arithmetic, uint32 tick/frame bounds, timestamp range, resource relationships and a necessary consumption-bit lower bound; **they cannot establish complete serialization/resource acceptance**. #27 must validate worst-density reachable windows and all continuation state against the actual schema/baseline limit, including reserved/random hearts and two widely separated cars. Do not treat the lower bound as a sufficient size estimate or enter Stage 4 without that gate.

Generated Go packages stay inside `apps/server`’s native module. Root generation task dependencies already establish ordering. Shared packages never import applications.
